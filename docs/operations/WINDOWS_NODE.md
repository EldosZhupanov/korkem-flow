# Узел KORKEM на Windows

Как поставить узел на компьютер, который у клиента уже стоит, и сделать так,
чтобы его видели планшеты в цехе — включая то, что сломается, если пропустить
шаг.

**Решение о форме поставки:** `ADR-0024`. Узел работает в WSL2, потому что
Frappe не работает на Windows нативно, а закупка мини-ПК откладывает пилот.

---

## Что здесь проверено, а что нет

Честно, по состоянию на **2026-09-01**:

| | статус |
|---|---|
| Стенд слушает `0.0.0.0` с наложением `wsl-node` | **проверено**, узел отвечает по адресу WSL |
| `Update-KorkemNodeAccess.ps1` — определение и план | **проверено** на настоящей Windows, `-DryRun` |
| `Update-KorkemNodeAccess.ps1` — создание проброса | **не проверено**, нужны права администратора |
| `Install-KorkemNodeAutostart.ps1` — разбор, `-DryRun`, симметрия удаления | **проверено** |
| `Install-KorkemNodeAutostart.ps1` — регистрация задачи и срабатывание | **не проверено** |
| Бэкап наружу из VHDX | **проверено целиком**, включая обнаружение порчи файла |

Не описывайте непроверенное как работающее. Первый настоящий прогон на машине
клиента — это и есть проверка; запишите её результат сюда.

---

## Порядок установки

### 1. WSL2 и Docker

```powershell
wsl --install -d Ubuntu
```

Перезагрузка. Затем Docker Desktop с включённой интеграцией WSL2, либо Docker
внутри самого дистрибутива.

### 2. Память

WSL по умолчанию забирает столько, что Windows начинает свопиться. В
`%USERPROFILE%\.wslconfig`:

```ini
[wsl2]
memory=8GB
processors=4
swap=8GB
autoMemoryReclaim=gradual
sparseVhd=true
```

`autoMemoryReclaim` обязателен: без него WSL никогда не возвращает Windows
пиковую выдачу. Изменения вступают в силу после `wsl --shutdown`.

### 3. Узел

Внутри WSL, из каталога `infra/frappe_bench`:

```sh
docker compose -f docker-compose.yml \
               -f docker-compose.pilot.yml \
               -f docker-compose.wsl-node.yml up -d
```

**Третье наложение обязательно, и это не оформление.** Без него стенд слушает
только `127.0.0.1` внутри WSL. Проброс на стороне Windows тогда настраивается
безупречно и указывает в пустоту — а с самого компьютера `localhost:8000`
отвечает 200, так что установка выглядит успешной.

Проверьте изнутри WSL:

```sh
curl -s -o /dev/null -w '%{http_code}\n' \
  -H "Host: korkem.localhost" "http://$(hostname -I | awk '{print $1}'):8000/api/method/ping"
```

Должно быть `200`. Если `000` — наложение не применено, дальше идти
бессмысленно.

### 4. Доступ из цеха

**PowerShell от имени администратора, из Windows** — не из оболочки внутри
WSL (см. «Ловушки» ниже).

```powershell
cd <путь>\infra\node\windows
powershell -ExecutionPolicy Bypass -File .\Update-KorkemNodeAccess.ps1 -DryRun
powershell -ExecutionPolicy Bypass -File .\Update-KorkemNodeAccess.ps1
```

Сначала всегда `-DryRun`: он покажет адрес WSL и что будет сделано, ничего не
меняя.

### 5. Автозапуск

```powershell
powershell -ExecutionPolicy Bypass -File .\Install-KorkemNodeAutostart.ps1 -DryRun
powershell -ExecutionPolicy Bypass -File .\Install-KorkemNodeAutostart.ps1
```

Задача поднимает дистрибутив, стек и переписывает проброс при каждом входе в
систему. Снять всё: тот же скрипт с `-Uninstall`.

### 6. Бэкап наружу

```sh
KORKEM_BACKUP_DIR=/mnt/d/korkem-backups ./scripts/backup_offsite.sh
```

Скрипт **отказывается** писать внутрь файловой системы WSL. Это его главное
свойство: архив внутри VHDX забирает тот же отказ диска, что и оригинал.

`site_config_backup.json` содержит `encryption_key`. Windows-диск не даёт
эффективных прав Unix — скрипт об этом предупреждает. Границу доступа к папке
с бэкапами задайте **Windows ACL**.

## Проверка, что цех действительно видит узел

С другого устройства в той же сети:

```
http://<адрес Windows в сети>:8000/api/method/ping
```

Адрес Windows смотрите так:

```powershell
Get-NetIPAddress -AddressFamily IPv4 | Where-Object { $_.PrefixOrigin -eq 'Dhcp' }
```

Не фильтруйте по имени интерфейса: оно переведено и на русской Windows
называется иначе.

## Ловушки

**Проверка «у себя» ничего не доказывает.** Замерено 2026-09-01: с самого
компьютера `localhost:8000` → 200, с адреса в сети цеха соединение не
устанавливается вообще, на порту 8000 в Windows не слушает никто. Проверять
надо с другого устройства.

**Адрес WSL меняется при каждой перезагрузке.** Правило проброса остаётся и
указывает в никуда. Ровно поэтому автозапуск — не удобство, а часть установки.

**`wsl --shutdown` убивает узел разом.** Команда встречается в любой инструкции
по WSL, и её выполнят, чтобы «освободить память».

**Обновления Windows перезагружают машину** в своё время. Без автозапуска цех
утром без системы.

**Не вызывайте `wsl.exe` из PowerShell, запущенного изнутри WSL.** Вложенный
вызов вешает мост interop целиком (`accept4 failed 110`), и из этой сессии WSL
перестают работать вообще все обращения к Windows. Контейнерам это не вредит.

**`.ps1` с русским текстом обязан быть UTF-8 с BOM.** PowerShell 5.1 — тот,
что идёт с Windows, — читает файл без BOM как Windows-1251, и разбор падает,
показывая на невиновные строки.

**Правило брандмауэра ставится только для Private и Domain.** Если сеть цеха
помечена в Windows как «Общедоступная», это надо исправить в настройках сети,
а не ослаблять правило.
