# Сервер с нуля — по шагам

**Дата:** 2026-09-03. Домен `korkem.asia` куплен в тот же день; сервера ещё нет.

Этот документ — единственный в `docs/operations/`, написанный по-русски и для
человека, который не администрирует серверы каждый день. Всё остальное там —
для инженера. Здесь нет ничего нового про архитектуру: это те же команды из
[`DEPLOYMENT.md`](./DEPLOYMENT.md), выстроенные в порядок, в котором их набирают
в первый раз, и с указанием, что произойдёт после каждой.

**Ничего из написанного ниже ещё не выполнялось на настоящем сервере.**
Проверено локально: preflight-проверки `deploy_pilot.sh` (обе ветки — и когда
исходники на месте, и когда их нет), оба профиля Caddy на внутреннем
сертификате. Не проверено: получение сертификата у Let's Encrypt, установка на
чистой Ubuntu, поведение сборки на 4 ГБ памяти. Эти три строки останутся здесь,
пока их не выполнят на живой машине.

---

## Что решено, и почему именно так

| решение | значение | почему |
|---|---|---|
| Имя сайта | `api.korkem.asia` | Frappe определяет сайт **по заголовку `Host`**. Сайт, созданный как `api.korkem.asia`, отвечает только на это имя. Отдельное имя оставляет `korkem.asia` свободным под лендинг, не трогая рабочий сайт |
| Профиль прокси | `app` | приложение на Android и Windows должно пускать людей внутрь. С профилем `webhooks` оно получит 404 на каждый запрос и напишет «нет связи с сервером» — правда, но бесполезная |
| Окружение | `pilot` | выключает режим разработчика, включает планировщик, и **все демонстрационные фикстуры начинают отказываться работать** |

**Переименовать сайт потом — отдельная операция со своей резервной копией.**
Не «просто настройка». Поэтому имя выбирается сейчас, до первого запуска.

---

## Шаг 1. Сервер

Нужен VPS с **Ubuntu 24.04 LTS**. Минимум, ниже которого не стоит опускаться:
**2 ядра, 4 ГБ памяти, 60 ГБ диска.**

Откуда это число, а не «1 ГБ хватит»:

| что занимает | сколько |
|---|---|
| исходники frappe + erpnext + crm (клонируются на сервер) | 3.8 ГБ |
| образ Docker | ~3 ГБ |
| bench: четыре приложения, `node_modules`, собранные ассеты | ~8 ГБ |
| база и резервные копии | растёт вместе с заводом |

Память тратится не на работу, а на **первую сборку**: `bench build` собирает
фронтенды erpnext и crm через esbuild, и это самый тяжёлый момент за всю жизнь
сервера. На 1 ГБ он не переживёт его вовсе.

Пароль или SSH-ключ от сервера мне не присылайте. Мне нужен только IP-адрес.

## Шаг 2. Своп — до всего остального

На 4 ГБ первая сборка может быть убита ядром по нехватке памяти. Своп — это
страховка, а не замена памяти, и стоит она две минуты:

```sh
fallocate -l 4G /swapfile && chmod 600 /swapfile
mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
free -h        # строка Swap должна показать 4,0Gi
```

## Шаг 3. Отдельный пользователь

Работать под `root` не нужно ни одной командой из этого документа, кроме первых
трёх.

```sh
adduser korkem
usermod -aG sudo korkem
```

## Шаг 4. Firewall

Наружу нужны ровно три порта. База и Redis наружу не смотрят вовсе — в
`docker-compose.yml` у них нет `ports:`, и это не случайность.

```sh
ufw allow 22/tcp && ufw allow 80/tcp && ufw allow 443/tcp
ufw enable && ufw status
```

**80 не опционален.** По нему Let's Encrypt проверяет, что домен действительно
ваш. Закрыть его — значит остаться без сертификата.

## Шаг 5. DNS

Только теперь, когда IP известен. В личном кабинете Hoster.kz: домены →
`korkem.asia` → DNS-хостинг.

```
A    korkem.asia             → IP сервера
A    www.korkem.asia         → IP сервера
A    api.korkem.asia         → IP сервера      ← сюда пойдёт приложение
A    downloads.korkem.asia   → IP сервера
```

Проверить **снаружи**, а не с сервера:

```sh
getent hosts api.korkem.asia
```

Пока эта команда молчит, шаг 9 не начинать: Caddy запросит сертификат, получит
отказ, и Let's Encrypt посчитает попытки.

## Шаг 6. Docker

```sh
curl -fsSL https://get.docker.com | sh
usermod -aG docker korkem     # затем выйти и зайти заново
docker compose version        # должно ответить, а не «unknown command»
```

## Шаг 7. Код

```sh
git clone https://github.com/EldosZhupanov/korkem-flow.git
cd korkem-flow
scripts/fetch_vendor.sh       # 3.8 ГБ, несколько минут
```

**Репозиторий закрытый.** `git clone` по HTTPS спросит логин и пароль, а пароль
GitHub больше не принимает — нужен либо токен доступа, либо deploy-ключ на
сервере. Это делается в две команды, но делать это надо на живом сервере: не
угадывайте, спросите — проведу по шагам.

**Шаг с `fetch_vendor.sh` забыть легче всего.** `frappe`, `erpnext` и `crm` не лежат в нашем
репозитории — там 3.8 ГБ чужой истории, закреплённой по коммитам в
`vendor.lock`. Docker не откажется примонтировать несуществующую папку: он
создаст пустую и запустится, а поломка всплывёт минут через десять внутри
bootstrap. С 3 сентября 2026 `deploy_pilot.sh` проверяет это первым делом и
останавливается, называя недостающее.

## Шаг 8. Настройки

```sh
cd infra/frappe_bench
cp .env.example .env
openssl rand -base64 24       # два раза — для двух паролей
nano .env
```

Заполнить:

```
MYSQL_ROOT_PASSWORD=<сгенерированный>
ADMIN_PASSWORD=<сгенерированный>
SITE_NAME=api.korkem.asia
KORKEM_ENV=pilot
KORKEM_GUNICORN_WORKERS=2
KORKEM_PUBLIC_HOST=api.korkem.asia
KORKEM_ACME_EMAIL=<ваша почта>
KORKEM_PROXY_PROFILE=app
```

`.env` не попадает в git и не должен. Ключи Gemini, Telegram и WhatsApp сюда
**не пишутся** — они вводятся в самом приложении и хранятся зашифрованными.

## Шаг 9. Запуск

```sh
cd ~/korkem-flow
scripts/deploy_pilot.sh --check     # ничего не меняет, только проверяет
scripts/deploy_pilot.sh             # первый запуск — до получаса
```

Скрипт останавливается на первом же условии, которое не выполнено, и говорит на
чём. Он не удаляет данные ни в одной ветке и делает резервную копию перед
миграцией.

## Шаг 10. Проверить, а не поверить

```sh
curl -sI https://api.korkem.asia/health          # 200
docker compose logs proxy | grep -i certificate  # какой сертификат выдан
```

Затем один проход по всей цепочке — от сказанного слова до счёта:

```sh
docker compose exec bench bash -lc \
  "cd ~/frappe-bench && bench --site api.korkem.asia execute korkem_manufacturing.chain_smoke.run"
```

**И одна проверка, которую нельзя сделать заранее** (см.
[`PRE_DOMAIN_CHECKLIST.md`](./PRE_DOMAIN_CHECKLIST.md)): войти по HTTPS и
посмотреть заголовок `Set-Cookie`. Если в нём нет `Secure` — остановиться.
Значит cookie сессии ходит по сети в виде, который можно украсть.

## Чего на сервере не будет

Flutter, Android SDK, Gradle и сборка под Windows на сервер не ставятся.
Приложения собираются там же, где собирались: Android — здесь, Windows — на
машине с Windows (`HANDOVER_WINDOWS_BUILD.md`). Сервер держит backend, и это
всё, что от него требуется. Добавить туда Android SDK — значит попросить те же
4 ГБ ещё раз.

## Известный пробел: резервные копии на сервере не заработают

`infra/frappe_bench/scripts/backup_offsite.sh` **отказывается** принимать любой
путь, кроме `/mnt/<буква диска>/…`:

```
KORKEM_BACKUP_DIR must be outside the WSL2 VHDX under /mnt/<drive-letter>/
```

Проверка написана для WSL, где копия внутри VHDX — это копия на том же диске,
который и пропадёт. Требование верное, но сформулировано через путь Windows, а
на Ubuntu такого пути нет. Значит строка cron из
[`BACKUP_AND_RESTORE.md`](./BACKUP_AND_RESTORE.md) на сервере не выполнится.

Чинить это вслепую нельзя: «вне машины» на VPS означает не «другая папка», а
другой носитель — подключённое блочное хранилище, объектное хранилище (S3 / R2)
или другой хост по ssh. **Куда именно** — решение владельца, и от него зависит
код. До того как оно принято, у пилота нет проверенной резервной копии, а
[`BACKUP_AND_RESTORE.md`](./BACKUP_AND_RESTORE.md) прав: копия, которую ни разу
не восстанавливали, — это не копия, а вера.
