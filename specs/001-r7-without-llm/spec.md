# Спецификация: пять действий без LLM

Дата: 2026-09-09. Статус: согласовано для реализации текущим поручением.
Источник: [ROADMAP, Г1 «Проверка R7»](../../ROADMAP.md#г1--korkem-service-api).
[Правила процесса](../../.specify/memory/constitution.md).
Это открытый инженерный критерий существующих действий; порядок новых
продуктовых функций из [NOW](../../NOW.md) не меняется.

## Сценарии пользователя

### US1 (P1): цех продолжает работу при отключённом AI
Дано: локальный узел, авторизованный сотрудник и действительные ERP-документы,
AI Settings.enabled=0 и отказ разрешения LLM-провайдера.
Когда сотрудник запускает производство, закрывает операцию, создаёт закупку,
принимает поставку или отгружает заказ через опубликованные функции API,
тогда в ERPNext изменяются соответствующие документы, количества и аудит.
Каждое действие проверяется отдельно.

### US2 (P1): отключение AI не отключает защиту
При отсутствии прав действие отвергается. Повтор того же намерения с тем же
ключом возвращает первый результат, не создаёт новых документов и проводок.

## Требования

- FR-001: запуск создаёт проведённое производственное задание и реальный
  перевод материала в НЗП; проверяется связь с заказом и движение по складу.
- FR-002: закрытие первой операции проводит Job Card, обновляет completed_qty
  и status соответствующей Work Order Operation.
- FR-003: закупка создаёт проведённый Purchase Order со связью с Material Request,
  положительной ценой из ERP и заказанным количеством.
- FR-004: приёмка проводит Purchase Receipt, увеличивает остаток и received_qty
  строки заказа поставщику.
- FR-005: отгрузка проводит Delivery Note, уменьшает остаток и увеличивает
  delivered_qty строки Sales Order.
- FR-006: во всех пяти проверках AI выключен, llm.resolve/get_provider
  не вызваны; бизнес-сервисы, ORM, права, scope и аудит не подменены.
- FR-007: все пять повторов с тем же idempotency_key сохраняют первый ответ,
  число документов, аудит и остатки; вызывающий пользователь определён.
- FR-008: пользователь без нужных прав и пользователь другой компании получают
  отказ на настоящих документах при отключённом AI.
- FR-009: каждая успешная команда оставляет Comment с пользователем и
  ссылкой на действие; данные каждого сценария и AI Settings откатываются без
  commit (общий demo baseline подготавливается до тестовых транзакций).
- FR-010: полный relevant backend-набор зелёный, отдельный модуль проходит
  дважды; отсутствие LLM доказано также при искусственно внесённом вызове.

## Критерии успеха

SC-001: 5/5 действий доказаны assertions в ERP, 0 обращений к LLM.
SC-002: права, scope, retry и аудит проверяются при том же outage.
SC-003: нет skip на отсутствующих данных; отсутствие обязательных fixtures
вызывает понятное падение.
SC-004: результаты имеют команды, числа и ограничения; вывод о пользе процесса
опирается на журнал, без выдуманной экономии.

## Границы

Пилот проверяет серверные функции API с настоящей БД. Он не является новым
HTTP/device E2E, доказательством отсутствия интернета или отсутствия установленного
korkem_ai. Flutter и runtime-код не меняются, если тесты не выявят дефект.
Новая инфраструктура идемпотентности и смена ролей не входят.

## Исходное состояние, до реализации

test_without_llm.py содержит пять тестов-обёрток: во всех подменяются domain,
scope, роли и аудит. Поэтому доказательств реального ERP-эффекта внутри
outage-набора: 0/5. Шестой тест проверяет импорты только API, без services.
Это наблюдение по коду, не результат исходного тестового прогона.
Известный пробел обнаружен при выборе задачи, до написания spec, и не
приписывается автоматике Spec Kit.
