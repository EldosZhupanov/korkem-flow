## 2. Настоящая причина. Она одна на все десять пунктов

**Примерно 5% всех запусков процессов на этой машине падают с `0xC0000005`.**

Не Flutter. Не проект. Не PATH. Измерено, а не выведено:

| что запускалось | падений |
|---|---|
| `cmd.exe /c exit 0` | 7 из 120 |
| `powershell.exe -Command "exit 0"` | 4 из 40 |
| `dart.exe --version` | 2 из 40 |

В журнале Windows те же падения у `where.exe`, `cmake.exe`, `netstat.exe`,
`wsl.exe`, `Orca.exe`. В отчёте WER у упавшего `where.exe` — **чистый список
модулей, только библиотеки Microsoft**, сбойный модуль `unknown`, адрес в частной
памяти. То есть портится память процесса на старте, а не внедряется чужая DLL.

### Что из твоих десяти пунктов было на самом деле этим

- **Пункт 5 «код 5» и `MSB8066 ... exited with code -1073741819`.** Это не «отказано
  в доступе» и не права на каталоги. `-1073741819` = `0xC0000005`. Каталоги,
  созданные из WSL, ни при чём — я удалил `build\`, `.dart_tool\`, `ephemeral\`
  и пересоздал их из Windows, ошибка осталась.

- **Пункт 7 «PATH нужно задавать целиком».** Вывод верный, объяснение неверное.
  Ты писал, что `WHERE` падает, наткнувшись на недоступную запись в PATH. На
  самом деле **падает сам `where.exe`** — тем же `0xC0000005`. `flutter.bat`
  проверяет наличие git и PowerShell через `WHERE /Q` (строки 26 и 35) и любой
  ненулевой код читает как «инструмента нет». Проверка `where.exe powershell.exe`,
  которую ты предлагаешь, ничего не покажет: она проходит в 95% случаев.

- **Пункт 9, кодировка.** Утверждение «`chcp 65001` снимает» — **неверно**.
  Я воспроизвёл `FormatException: Unexpected extension byte` при уже выставленном
  `chcp 65001`. Настоящая ошибка в тот момент пряталась за этим исключением: это
  был крах дочернего процесса, а не кодировка. Дефект `tool_backend.dart`
  (жёсткий `utf8.decoder` на выводе потомка) реален и клиента ударит, но
  сегодняшнюю сборку ломал не он.

### Новые маски той же причины, которых в передаче не было

- `IconTreeShakerException: Font subsetting failed with exit code -1073741819` —
  падал `font-subset.exe`. Отсюда `--no-tree-shake-icons`.
- `Target kernel_snapshot_program failed: Exception` — падал компилятор Dart.
  Тот же шаг с третьей попытки прошёл сам, без единой правки.
- `ProcessStarter::StartForExec failed: Отказано в доступе (process_win.cc:703)` —
  `CreateProcess` вернул `ERROR_ACCESS_DENIED`.
- `Failed to update packages`, `Unable to generate build files` — то же самое.

## 4. Как всё-таки собралось

Идея простая: **сборка инкрементальна между провалившимися попытками.** Каждый
успешный подшаг остаётся на диске — разрешение зависимостей, `flutter assemble`,
генерация CMake, каждый объектный файл MSVC. Поэтому цикл повторов сходится, даже
если ни один отдельный проход не может выжить целиком. Ушло около 20 попыток.

Что уменьшало число запусков процессов на попытку:

- `--no-pub` — зависимости уже разрешены, а `pub get` каждый раз стоит десятков
  запусков;
- `--no-tree-shake-icons` — убирает четыре запуска `font-subset.exe`, каждый из
  которых мог упасть;
- две правки Flutter SDK (см. ниже) — убирают 3–4 запуска на каждый вызов
  `flutter.bat`, а он вызывается 3 раза за попытку, включая вложенные из MSBuild.

**Две ловушки в самом цикле повторов, на которых я потерял время:**

1. **Нужен таймаут на попытку и добивание зависших процессов.** Упавший потомок
   оставил `dart.exe` висеть с нулевым CPU, и `Start-Process -Wait` заблокировался
   навсегда. Цикл выглядел работающим и стоял.
2. **Файлы `.bat` писать только латиницей.** Русский комментарий в UTF-8 сломал
   разбор файла в `cmd`: переменная стала пустой, и цикл 30 раз бодро запускал
   пустоту. Выглядело как работа, работой не было.
