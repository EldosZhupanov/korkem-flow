# PROJECT.md

# AI Furniture Manufacturing Operating System
## Product Constitution

Version: 1.0

---

## Mission

Build the most intelligent AI-native operating system for furniture manufacturing companies.

This is not another ERP.

This is not another CRM.

This is not another task manager.

This product must become the digital brain of an entire furniture factory.

The application should manage production instead of simply recording production.

Humans supervise. AI operates.

---

## Vision

The long-term objective is to create software that can autonomously coordinate an entire furniture factory.

The software should continuously observe, analyze, predict and optimize every manufacturing process.

Every action inside the company should become measurable.

Every decision should become data-driven.

Every repetitive task should eventually become automated.

---

## Product Identity

The software is an Operating System.

Not an ERP. Not a CRM. Not a Dashboard. Not a Database.

Everything revolves around intelligence.

AI is the primary interface. Traditional interfaces exist only when necessary.

---

## Core Philosophy

Instead of asking "What information should the user enter?" — ask "What information can AI determine automatically?"

Instead of asking "What buttons should exist?" — ask "What conversation should happen?"

Instead of asking "What screen should we build?" — ask "What problem should disappear?"

---

---

## Product Principles

Everything should have one source of truth.

Everything must be traceable.

Everything should be measurable.

Everything should be explainable.

Everything should be observable.

Everything should be searchable.

Everything should be automatable.

---

## Core Entity

The central entity is **Production Order**.

Everything references Production Order.

Never design modules around Customers. Never design modules around Sales.

Everything eventually becomes production.

---

## Production Lifecycle

Lead → Customer Qualification → Measurement → Room Photos → Design →
Revision → Customer Approval → Quotation → Contract → Deposit →
Material Planning → Inventory Validation → Purchasing → Supplier Confirmation →
Material Arrival → Warehouse Allocation → Production Planning → Cutting →
Edge Banding → CNC → Drilling → Painting → Assembly → Quality Inspection →
Packaging → Delivery Planning → Delivery → Installation → Acceptance →
Warranty → Archive

Nothing bypasses this workflow.

## AI Responsibilities

AI should eventually perform:

Customer qualification, production planning, task distribution, material
estimation, production scheduling, warehouse optimization, purchase
suggestions, deadline prediction, risk prediction, delay prediction,
financial forecasting, quality monitoring, executive reporting, meeting
summaries, document generation, knowledge retrieval, employee assistance,
training assistance, analytics, decision support.

## UX Principles

Minimal. Fast. Zero clutter. Zero ERP complexity.

Everything should require almost no training.

Mobile-first. Tablet-first on factory floor. Desktop for management.

---

## AI User Experience

Users should not navigate menus. Users should ask AI.

Examples:

- "Which orders are delayed?"
- "Show today's production."
- "Assign today's cutting."
- "Find missing materials."
- "Create purchase order."
- "Generate weekly report."
- "Why is kitchen order #103 delayed?"

AI should answer directly.

---

## Dashboard Philosophy

Dashboards should explain, not decorate.

Every chart must answer a business question.

Every metric must support a decision.

No useless widgets. No vanity metrics.

---

## Data Philosophy

Never duplicate data.

Everything should be normalized.

Events should be immutable.

History should never disappear.

Every change should be auditable.

---

## Architecture Goals

Highly modular. Domain driven. API first. AI first. Event driven.
Plugin friendly. Cloud ready. Offline capable. Scalable. Observable.
Maintainable.

---

## Long-term Expansion

Furniture → Wood Manufacturing → Metal Manufacturing → Construction → General Manufacturing

The architecture must support expansion without major redesign.

---

## Definition of Success

The software becomes the central operating system of a factory.

Managers stop using spreadsheets.

Employees stop asking managers what to do.

Production becomes self-organizing.

AI becomes the first place users interact with.

The software feels like hiring a world-class operations team instead of buying software.

---

## Non-Goals

Do not build another generic ERP.

Do not clone ERPNext. Do not clone Monday. Do not clone ClickUp. Do not clone Bitrix24.

Build something fundamentally better by combining proven ERP capabilities with AI-native workflows.

---

## Final Principle

Every line of code should move the product closer to becoming an autonomous operating system for manufacturing.

If a feature does not improve that mission, question whether it should exist at all.
