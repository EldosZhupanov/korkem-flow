### A. Какую проблему решает
ERPNext — полнофункциональная open-source ERP система для малого, среднего и крупного бизнеса. Охватывает производственное планирование (MRP), управление складом (WMS), закупки, продажи, бухгалтерский учет, кадры и зарплату. Для KORKEM является базовым бэкенд-движком и источником производственных паттернов.

---

### B. Архитектура системы
- **Модульная структура приложений Frappe (`erpnext/`):**
  - `manufacturing`: спецификации (BOM), производственные заказы (Work Order), сменные карточки операций (Job Card), маршруты (Routing), рабочие центры (Workstation).
  - `stock`: партионный учет (Stock Entry, Stock Ledger Entry, Serial and Batch Bundle), склады, перемещения, резервы (Stock Reservation Entry).
  - `buying`: цепочка закупок (Material Request -> Purchase Order -> Purchase Receipt -> Purchase Invoice).
  - `selling`: продажи (Quotation -> Sales Order -> Delivery Note -> Sales Invoice).
  - `accounts`: план счетов, проводки (GL Entry), платежи (Payment Entry).
  - `subcontracting`: давальческое сырье и субподряд (например, выездная покраска фасадов или раскрой на стороннем ЧПУ).

---

### C. Ключевые модули и файлы
- `erpnext/manufacturing/doctype/bom/` — структура изделия, материалы, операции и себестоимость.
- `erpnext/manufacturing/doctype/work_order/` — производственное задание на выпуск готовой продукции или полуфабриката.
- `erpnext/manufacturing/doctype/job_card/` — сменное задание на конкретную технологическую операцию для рабочего центра и оператора.
- `erpnext/stock/doctype/stock_entry/` — движение ТМЦ: списание сырья в производство (`Material Consumption for Manufacture`), оприходование готовой продукции (`Manufacture`), возврат остатков.
- `erpnext/stock/doctype/stock_reservation_entry/` — жесткое резервирование остатков склада под конкретный заказ продаж.

---

### D. Важные доменные абстракции и их мебельная адаптация
В классическом ERPNext модель универсальна (подходит и для консервного завода, и для машиностроения). Для KORKEM необходима специализированная адаптация под мебельный цех:

```
+-------------------------------------------------------------------------------+
|                             КЛАССИЧЕСКИЙ ERPNEXT                              |
| Item -> BOM -> Routing -> Work Order -> Job Card -> Stock Entry -> Finished   |
+---------------------------------------+---------------------------------------+
                                        |
                                        v
+-------------------------------------------------------------------------------+
|                      МЕБЕЛЬНАЯ АДАПТАЦИЯ ДЛЯ KORKEM                          |
|                                                                               |
|  [Furniture Order] (Шкаф-купе / Кухня по замеру)                              |
|         │                                                                     |
|         ├─► [BOM из БАЗИС XML]                                                |
|         │     ├── Панели (ЛДСП 16/18/25 мм, м², направление текстуры)        |
|         │     ├── Фасады (МДФ, плёнка/эмаль, тип фрезеровки, патина)         |
|         │     ├── Кромка (ПВХ 0.4/1/2 мм, погонные метры)                     |
|         │     └── Фурнитура (петли, направляющие, конфирматы, ручки)          |
|         │                                                                     |
|         ├─► [Маршрут операций (Routing)]                                      |
|         │     1. Раскрой плит (Форматно-раскроечный / ЧПУ Nesting)           |
|         │     2. Кромкооблицовка (Кромочный станок: прямолин. / криволин.)    |
|         │     3. Присадка / Сверление (Сверлильно-присадочный станок)         |
|         │     4. Фрезеровка фасадов (Фрезерный ЧПУ)                          |
|         │     5. Прессование плёнки / Покраска (Мембранно-вакуумный пресс)    |
|         │     6. Предварительная сборка модулей (Сборочный цех)               |
|         │     └── Упаковка и маркировка (Упаковочный стол)                    |
|         │                                                                     |
|         ├─► [Сменные карточки цеха (Shop Floor Tasks / Job Cards)]            |
|         │     └── QR-код детали/пакета, расчёт сдельной оплаты оператора       |
|         │                                                                     |
|         └─► [Материальный учет (Material Consumption)]                        |
|               ├── Списание целых плит со склада                               |
|               ├── Оприходование деловых обрезков (Деловой остаток)            |
|               └── Списание брака и технологических потерь                     |
+-------------------------------------------------------------------------------+
```

### E. Что уже есть в KORKEM
- KORKEM использует `erpnext` как runtime dependency.
- В `korkem_manufacturing/services/` реализованы:
  - `bazis.py`: импорт XML из «Базис-Мебельщик» с созданием Items и многоуровневого BOM.
  - `production.py`: запуск Work Order с проверкой физической доступности плит на складе.
  - `shop_floor.py`: регистрация выполнения Job Card мастерами цеха.
  - `materials.py` и `catalogue.py`: справочники декоров, плит, кромки и фурнитуры.

---

### F. Чего не хватает в KORKEM по сравнению с ERPNext
- **Учета деловых остатков (Offcut / Remnant Management):** В мебельном цехе плита ЛДСП 2800х2070 раскраивается с остатком кусков 1200х600. В стандартном ERPNext нет понятия делового остатка — списывается либо вся плита, либо дробное количество листов (что создает хаос в инвентаризации).
- **Сдельной оплаты труда (Piece-rate Payroll Integration):** Оператор форматки получает оплату за квадратный метр распила или количество пропилов; кромщик — за метр кромки. В KORKEM фиксация операции есть в `shop_floor.py`, но нет автоматического начисления сдельного заработка на лицевой счет рабочего.
- **Инспекции качества (Quality Inspection):** Отсутствует фиксация брака фасадов (сколы, отслоение пленки) перед передачей на сборку.

---

### G. Что KORKEM должен перенять концептуально
1. **Строгую синхронизацию складского статуса и резервов:**
   Использовать ERPNext `Stock Reservation Entry` при подтверждении предоплаты заказа, чтобы плиты под проект клиента не могли быть израсходованы на другой заказ.
2. **Связку операции и сдельного тарифа:**
   В `Job Card` добавить расчет стоимости работы мастера: `earned_amount = completed_qty * piece_rate`.

---

### H. Что KORKEM сознательно НЕ должен перенимать
- **Избыточную бюрократию интерфейсов ERPNext Desk:**
  Классический Desk ERPNext перегружен сотнями полей, доктайпов и вкладок, непригодных для планшета пыльного мебельного цеха.
  В KORKEM рабочий и директор должны работать через лаконичный Flutter UI (экран смены, большие кнопки, сканирование штрихкодов), а не через веб-формы стандартного ERPNext.

---

### I. Оценка трудоемкости внедрения
- Мебельные статусы резервирования и авторезерв по оплате: **1–2 дня**.
- Сдельный тариф в карточке сменного задания: **2 дня**.

---

### J. Архитектурные риски
- Конкурентные блокировки таблиц `tabStock Ledger Entry` и `tabBin` при одновременных списаниях. Требует изоляции транзакций и группового проведения документов.

---

### K. Лицензионные последствия
- **GPL-3.0.** ERPNext уже подключен как отдельное приложение в бенче. Код `korkem_manufacturing` пишется как независимое расширение по Frappe Framework Architecture.

---

### L. Итоговая рекомендация архитектора
**Одобрено к усилению:**
1. Использовать ядро ERPNext для резервирования материалов и производственных цепочек.
2. Ни в коем случае не выводить операторов в Desk ERPNext — все операции вести строго через мобильный/терминальный Flutter-клиент KORKEM.
