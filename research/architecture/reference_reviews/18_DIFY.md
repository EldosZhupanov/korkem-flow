### A. Какую проблему решает
Dify — популярная платформа для разработки и оркестрации LLM-приложений. Решает задачу визуального конструирования чат-ботов, агентских пайплайнов, подключения баз знаний (RAG) и интеграции внешних инструментов без ручного написания boilerplate-кода.

---

### B. Архитектура системы
- **Серверная архитектура (`api/`):**
  - `api/core/workflow`: движок выполнения графов узлов (LLM, Code, Knowledge Retrieval, Tool, HTTP Request, Variable Assign).
  - `api/core/rag`: пайплайн обработки документов (парсинг PDF/Word, чанкинг, эмбеддинги, векторный поиск, гибридный поиск с реранкером).
  - `api/core/tools`: среда изолированного выполнения инструментов с динамической подгрузкой манифестов YAML.
  - `api/core/agent`: стратегии агентов (Function Calling, ReAct).
- **Слой баз знаний (Knowledge Base):**
  Хранение регламентов, стандартов качества, инструкций по сборке с семантическим поиском релевантных фрагментов для контекста LLM.

---

### C. Ключевые модули и файлы
- `api/core/workflow/workflow_entry.py` — точка входа и цикл исполнения графа рабочего процесса.
- `api/core/rag/datasource/retrieval_service.py` — сервис гибридного поиска по базе знаний.
- `api/core/tools/tool_engine.py` — запуск и валидация внешних инструментов.

### D. Мебельные сценарии знаний в KORKEM
В мебельном цехе есть масса специфических знаний, которые нужны и мастеру, и клиенту:
1. **Инструкции по сборке и фурнитуре:**
   «Как отрегулировать петли Blum Clip-Top с доводчиком?», «Какое сверло нужно под конфирмат 7х50?».
2. **Технические ограничения материалов:**
   «Какая минимальная ширина планки для врезки профиля Gola?», «Какой максимальный пролет полки из ЛДСП 16 мм без ребра жесткости (чтобы не провисала под посудой)?».
3. **Регламенты работы с клиентом и гарантии:**
   «Гарантия на кухни — 24 месяца при отсутствии залития водой, гарантия на фурнитуру — 5 лет».

---

### E. Что уже есть в KORKEM
- В `korkem_ai/doctype/memory_fact/` есть хранение фактов о клиентах и компании.
- В `korkem_ai/doctype/work_instruction/` есть производственные задания работникам.
- Нет векторной базы данных (Postgres/pgvector/Qdrant не установлены; используется MariaDB).

---

### F. Чего не хватает в KORKEM по сравнению с Dify
- **Локальной базы знаний (Scoped Knowledge Retrieval):**
  Ассистент KORKEM сейчас полагается только на системный промпт и доменные tools. Если клиент в WhatsApp спрашивает: «А вы можете сделать кухню без ручек?», ассистент отвечает общими фразами из весов модели, а не точными регламентами фабрики.
- При этом, как отмечено в `docs/architecture/ai_agent_gap_analysis.md`, **RAG не может отвечать о текущей цене, остатке на складе или статусе заказа** — источником истины для оперативных данных всегда является SQL/Domain Service. База знаний нужна только для статических технологических регламентов.

---

### G. Что KORKEM должен перенять концептуально
1. **Легковесный локальный поиск по регламентам (BM25 / Full-Text Search):**
   Вместо тяжелого векторного кластера использовать встроенный полнотекстовый поиск MariaDB (`MATCH ... AGAINST`) по документам `Knowledge Article` фабрики. Это дает нулевой оверхед по памяти и работает на 100% офлайн (R6, R7, R8).

---

### H. Что KORKEM сознательно НЕ должен перенимать
- **Разворачивание стека Dify (Weaviate, Celery, тяжелый Next.js):** Это убило бы локальный узел мебельного цеха по памяти.
- **Предоставление RAG права отвечать по ценам и остаткам:** Запрещено категорически.
