### A. Какую проблему решает
n8n — ведущая open-source платформа автоматизации рабочих процессов и интеграций (workflow automation). Решает задачу связывания разрозненных сервисов, очередей, баз данных и вебхуков через визуальный DAG-граф из нод (триггеры, преобразования, условия, действия, интеграции).

---

### B. Архитектура системы
- **Монорепозиторий (`packages/`):**
  - `packages/workflow`: чистое ядро выполнения графов (Node execution engine, Data routing, Expression evaluation, Parameter resolution).
  - `packages/core`: сервисы диспетчеризации выполнения (`WorkflowExecute`, `ExecutionRepository`, `WebhookService`, `Credentials`).
  - `packages/nodes-base`: коллекция готовых узлов (HTTP Request, Webhook, If, Switch, Schedule, Telegram, WhatsApp, Slack, Postgres, etc.).
- **Модель данных выполнения (Execution Pipeline):**
  - Каждая нода принимает массив элементов: `INodeExecutionData[] = [{ json: {...}, binary: {...} }]`.
  - Поток данных непрерывен и типизирован; выход предыдущего узла передается во вход следующего.
  - Поддержка условных ветвлений (`IF`, `Switch`), циклов и агрегаций.
- **Обработка сбоев и Human-in-the-loop:**
  - Настраиваемые повторы при сбое узла (`Retry on Fail`, экспоненциальный бэкап).
  - Ожидание внешнего вебхука или действия человека (`Wait` node, аппрув в Telegram).

---

### C. Ключевые модули и файлы
- `packages/workflow/src/WorkflowExecute.ts` — алгоритм топологической сортировки и пошагового выполнения графа узлов.
- `packages/core/src/execution-engine/` — управление жизненным циклом запуска задачи (Start, Running, Success, Waiting, Error).
- `packages/core/src/webhooks/webhook.service.ts` — регистрация и безопасная диспетчеризация входящих вебхуков.
- `packages/nodes-base/nodes/If/` — логика условной фильтрации данных по предикатам (`equals`, `contains`, `greaterThan`).

---

### D. Важные доменные абстракции
1. **Trigger (Триггер события):** Источник запуска цепочки (событие в системе: `OrderCreated`, `PaymentReceived`, `ProductionDelayed`, или внешний вебхук).
2. **Condition (Условие / Фильтр):** Логический предикат над полями полезной нагрузки (например: `order.total_amount > 500000 AND order.advance_paid == false`).
3. **Action (Действие):** Вызов детерминированной доменной команды (отправить сообщение, назначить задачу мастеру, зарезервировать плиты, создать заявку снабженцу).
4. **Execution Log:** Полный след каждого срабатывания правила с сохраненными входными данными, результатом каждого шага, временем выполнения и статусом.

---

### E. Что уже есть в KORKEM
- В `korkem_manufacturing/domain_events.py` есть синхронная шина событий (`emit()`), уведомляющая подписчиков по хукам Frappe.
- В `korkem_ai/channels/` есть обработка входящих вебхуков Telegram и WhatsApp.
- В `korkem_manufacturing/services/reminders.py` есть периодические проверки («Заявка без исполнителя», «Просроченный замер»).

---

### F. Чего не хватает в KORKEM по сравнению с n8n
- **Пользовательского движка правил (KORKEM Automation Engine):**
  Владелец цеха не может сам настроить правило. Любая новая автоматизация («Если клиент не ответил на КП 2 дня — отправить напоминание в WhatsApp») требует написания Python-кода разработчиком.
- **Отсутствия визуального журнала выполнения правил:** При сбое автоматического уведомления нет интерфейса, где директор или администратор может увидеть: «Правило сработало в 14:02, условие выполнилось, отправка в WhatsApp завершилась ошибкой 401».

---

### G. Что KORKEM должен перенять концептуально
1. **Канонический легковесный мебельный Automation Engine:**
   Внедрить в `korkem_manufacturing` декларативную модель:
   ```
   WHEN <TriggerEvent>
   IF   <ConditionExpression>
   DO   <ActionCommand(args)>
   ```
   *Примеры критических мебельных правил:*
   - `WHEN OrderCreated IF measurement_missing == True DO CreateTask(role="MEASURER")`
   - `WHEN PaymentReceived IF payment_type == "Deposit" DO ReserveMaterials() AND ReleaseToProduction()`
   - `WHEN DueDateApproaching IF days_left <= 2 AND status != "Assembly" DO NotifyOwner("Угроза срыва срока заказа!")`
   - `WHEN StockBelowThreshold IF item_group == "ЛДСП" DO CreatePurchaseRequest()`
2. **Execution Run Log:**
   Сохранять статус каждого выполнения автоматизации (`AutomationRun`: `rule_id`, `trigger_event`, `matched`, `action_results`, `error`, `duration_ms`).

---

### H. Что KORKEM сознательно НЕ должен перенимать
- **Тяжелый визуальный редактор узлов на канвасе (Flow Canvas):**
  Для владельца мебельного цеха из 5–10 человек перегруженный граф n8n или Zapier избыточен и пугает. Достаточно простого табличного интерфейса «Если произошло событие -> При условии -> Выполнить действие».
- **Стек Node.js / TypeScript:** Движок автоматизации в KORKEM должен работать нативно внутри Python/Frappe, вызывая существующие доменные сервисы без межпроцессных накладных расходов.

### I. Оценка трудоемкости внедрения
- Разработка ядра `korkem_manufacturing.services.automation` (Trigger -> Condition -> Action) + DocTypes `Automation Rule` и `Automation Run`: **2–3 дня**.

### J. Архитектурные риски
- Зацикливание автоматизаций (Infinite Loop): когда действие правила вызывает событие, запускающее то же правило.
  *Защита:* Ограничение глубины вызовов (`max_recursion_depth = 3`) и запрет триггеров на собственные действия.
