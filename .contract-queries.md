# КОНТРАКТ query-эндпоинтов. Обязателен для обеих сторон.

Этот файл — источник правды. Если сервер и клиент разойдутся, прав этот файл.

## korkem_manufacturing.api.queries.work_orders

Аргументы: status: str|None, search: str|None, limit: int = 20, offset: int = 0
Аргумента company НЕТ и быть не может — scope решает сервер.

Ответ:
{
  "orders": [                       <- ключ именно "orders", не "work_orders"
    {"name": str,
     "production_item": str|null,
     "item_name": str|null,
     "qty": float,
     "produced_qty": float,
     "status": str,
     "planned_end_date": str|null,   <- ISO дата или null
     "actual_end_date": str|null,
     "sales_order": str|null,
     "bom_no": str|null}
  ],
  "total": int,                     <- сколько всего, с учётом фильтров и поиска
  "limit": int,
  "offset": int
}

## korkem_manufacturing.api.queries.stock

Аргументы: warehouse: str|None, search: str|None, limit: int = 50, offset: int = 0

Ответ:
{
  "items": [
    {"item_code": str,
     "item_name": str|null,
     "warehouse": str,
     "actual_qty": float,
     "reserved_qty": float,
     "projected_qty": float,
     "stock_uom": str|null}
  ],
  "total": int,
  "limit": int,
  "offset": int
}

## Правила для обеих сторон

- Пустой список — это `[]`, никогда не null.
- Числа могут прийти строкой (Frappe так делает на некоторых путях) —
  клиент обязан принимать оба.
- Отсутствие значения — `null`, не пустая строка и не 0.
- Клиент НЕ вычисляет ничего сам: не суммирует, не считает остатки,
  не выводит готовность. Что сервер сказал, то и показывает.
