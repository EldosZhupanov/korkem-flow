# HYPODIVE Builder Handoff

## 1. Objective

User/scientific objective, selected mode, success criterion, constraints, non-goals.

## 2. Strongest Claims

C1, C2, C3... Exact claims, type, scope, status, evidence pointer.
Include only claims actually made; do not invent three claims to fill this template.

## 3. Canonical Implementation

Files/classes/functions; caller paths; legacy paths and remaining migrations.

## 4. Architecture Decisions

ADR links, realistic alternatives, trade-offs and reversal/kill conditions; N/A if routine.

## 5. Invariants

Invariant → enforcing code → test, including relevant failure boundaries.

## 6. Test Evidence

Commands, environment, observed results, skipped/failed checks and limits.

## 7. Empirical Evidence

Raw result paths/IDs, analysis commands, generated tables, pairing and uncertainty.
State N/A if no empirical claim or no experiment was authorized.

## 8. Assumptions

Truth/model/noise, data access, execution, permissions and deployment assumptions as relevant.

## 9. Known Weaknesses

Unresolved defects, scope restrictions, holdout access, fidelity/reproduction limitations.

## 10. Simplest Plausible Alternative

The strongest simple implementation or explanation of the apparent gain.

## 11. Suggested Kill-Tests

Cheapest discriminating check first; expected observation that would refute each claim.
Suggestions do not direct the falsifier toward a desired outcome.

## 12. Freeze Point

Branch; evaluated commit; results commit if available; config; seed/split manifest;
canonical implementation; claim IDs; raw results; analysis; test command; environment;
manifest path; known weaknesses. Label unavailable fields explicitly.
